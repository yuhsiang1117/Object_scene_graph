A map that is confidently wrong

Most object-goal navigation assumes an incomplete map. This system is built for a map that is actively wrong: it says the bowl is on the desk, and the bowl has been moved to the bed. Every mechanism below exists to let a map be wrong, notice, and recover.

Protocol

The staleness is the experiment

The benchmark runs in two passes. Pass 1 explores a static layout and writes one map snapshot per scene. The objects are then moved. Pass 2 starts from that snapshot, so the agent begins each episode already believing something false.

This is deliberate and it is the whole point. An agent that rebuilds its map from scratch every episode is never wrong about anything, and therefore measures nothing.

Two protocol choices make the numbers harder, not easier. The prior map is genuinely stale rather than merely absent (ycb.map_in), and a query gets several navigation attempts — because DualMap, the system being compared against, allows several. Scoring a single attempt would have flattered these results.

Control

One step

NavAgent.act(frame) is the entire control loop, and it reads as its own summary. Each line is one module; nav_agent.py owns the state machine and nothing else.

Before this refactor the same method opened with forty lines of multi-floor bookkeeping — inert in every run of this benchmark — so the path an episode actually takes could not be read off the file.

Mechanisms

Four things a static map cannot do

Each carries the measurement that chose its constants. In this codebase a number is not allowed to exist without one.

1 · Presence — is it still there?

A binary Bayes filter in log-odds with three channels kept deliberately apart. The middle one is what a static map lacks entirely.

E — would we have seen it if it were there — is the whole mechanism, and the depth buffer decides it almost for free. An object that was removed leaves the surface behind it visible, so measured depth lands beyond the expected band. An object hidden by a door reads nearer. One signed comparison separates the frame that must update the belief from the frame that must not — which is why only the near side is gated.

Measured

The clamp is asymmetric on purpose — 6.0 down, 3.0 up. A sighting is worth +2.5 and a miss −0.9, so a symmetric clamp saturates after three sightings and then needs seven clean misses to undo. That is exactly how a ghost survives an agent standing in front of its empty shelf.

min_presence = 0.45 is arithmetic, not taste. A belief reloaded from a prior map at 0.82 lands at 0.485 after one detector-strength absence reading and 0.36 after a VLM one. One detector miss does not retire a track; a second does; one VLM answer is decisive alone.

2 · Identity — is it mine?

Presence cannot answer this, and that is not a gap to patch but a different question. A false positive is an object that really is there. Every look that disproves it as the target also re-detects it as an object and pins its belief at the positive clamp.

Measured

With the identity channel off, one episode committed to the same wrong track 251 times in 500 steps, its belief held at the clamp through 250 absence readings. Turning it on took repeat commits to 6 and livelocked episodes from 7 → 0.

max_identity_rejections = 2: one arrival can end on a bad heading or a consumed path — two is a decision.

3 · The search posterior — then look there

DualMap’s answer to a failed candidate is the next-highest similarity, plus an ignore list discarded when the query ends: the discrete search problem with the belief thrown away. No model of where the object went, no cost of getting there, no memory of what was searched, and no way for the retry loop to decide to go explore instead.

The classical result is that the optimal order is by b(x)·d(x)/c(x), and after an unsuccessful look b(x) ← b(x)·(1−d(x)). The pleasing part: frontier selection already computes exactly this index as score / path_cost. So nothing new is added — the candidate set is widened to include the surfaces an object could have been moved to, and the two compete.

Why multiply

A visit multiplies belief rather than zeroing it, so a surface glanced at from four metres stays plausible and one inspected closely mostly stops being. An ignore list cannot tell those apart, and forgets both. DualMap’s is the degenerate case b ← 0 after a single look.

b(x) decays as exp(−d/L) from where the object was last believed to be. L is 1.0 m, not the 4.0 m it started at, because the benchmark’s own displacements say so: in-anchor moves have a median of 0.72 m and cross-anchor 6.06 m — a short mode plus a long tail, not one exponential with a 4 m scale.

The bug

The floor was doing damage, and instructively. max(exp(−d/L), floor) does not mix two hypotheses, it clips: every candidate past L·ln(1/floor) gets an identical prior, so the whole far field ties and its order collapses to track id — precisely the regime a cross-anchor move lives in. Removing it took cross-anchor from 1/57 to 7/57.

A second trap: ordering and scale are different decisions. Sharpening proximity improved every ranking number and silently switched the search line off — a pilot went from 27 surface inspections over six episodes to one, because every candidate past the first few now scored below any frontier.

4 · Absence on arrival

Walking to where the map said an object was, finding nothing, and stopping there is how a stale map converts a success into a confident failure — and teaches the map nothing, so the next episode makes the same trip. Arriving without a sighting is an observation.

Two sensors answer, with their own measured error rates, and the filter does not care which produced the reading. That is the payoff of writing presence as a filter rather than as detector bookkeeping.

Measured

Detector silence over a whole approach is r = 0.8: 6790 logged expectations give a 0.812 detection rate in the regime the visibility gate admits. The VLM, forced to choose on a zoomed crop, scored 17/20 on real present/absent cases.

So one trusted “no” is worth about two detector misses — log(0.15/0.98) against log(0.5/0.95) — with no fusion code at all.

Three things it deliberately does not do, each a mistake that was made and measured:

  • A failed call is no information, never absence. Treating a network error, or a “blocked” answer about an obstructed view, as evidence would quietly delete objects behind doors.
  • The detector’s silence only counts where a detection was expected. An unexpected miss says something about the view, not about the world.
  • Abandoning is not blacklisting. On a correct map the agent once abandoned the bowl, wandered, and ended the episode standing 0.088 m from the goal — inside the success radius — unable to stop, because the only track that could have been the answer had been struck off for good.

And one thing the arrival sweep does not do: apply a negative reading per frame. Twelve looks at the same object from the same pose are not twelve independent observations — same range, lighting and viewing angle on the same geometry — so multiplying their likelihoods turns one correlated detector failure into overwhelming evidence of absence. Doing it dropped SR from 0.429 to 0.286. The sweep’s job is to give the detector a chance, not to vote.

L, and how

L and M are the first conditions to lift both halves instead of trading between them: M is +16 episodes on K against a noise floor of about one, and the best of the ladder on every column. None of the three changes came from tuning. All came from tracing the largest failure bucket -- 22 of 53 failures where the detector named the object at its new pose and no track within 0.5 m ever existed -- to two defects that break principles stated elsewhere in this codebase's own comments.

An unreachable candidate was struck off permanently, and the question was asked about the object's own position rather than the pose the agent would drive to. Six of 00829's thirty-six target poses are off-navmesh with a reachable viewpoint -- shown with no detector in the loop.

And a glance retired a surface once per keyframe, unbounded: 64% of the candidate set written off per episode, most of it never visited. Bounding it at 1 - search_detect_prob took surfaces retired from 52 of 82 to 1 of 54 and roughly doubled inspections per episode, 2.15 → 4.01.

And the map discarded 33% of the times the detector named the target. In eleven episodes it discarded every naming — no track, so no candidate, so no approach, so the detection never got closer or bigger. All eleven failed. Five of them were a contradiction rather than a threshold: detector.class_conf lowers the detector to 0.20 for the four weakest classes and min_det_score 0.35 then discards everything they gained — boxes of 5146, 5077, 3102 px, thrown away on score alone. Two thresholds for one decision, in two config groups, the tighter one downstream.

The gain is not evenly spread, and one scene refuses to move: 00829 goes 21 → 32 of 36 and 00880 11 → 16 of 30, while 00848 is 11/30 under all three conditions and identical in both halves every time. Thirteen of its nineteen failures never name the target at all. That is a coverage-and-perception scene, and none of these changes touches it — while 00829, where the gain is largest, is the scene most of the tuning was done on.

The two difficulties traded against each other, up to K. cross_anchor trails in_anchor by 0.1–0.35 throughout, which is intuitive: a cross-room move forces a real search rather than a longer look nearby. No condition is best at both. J → K changed two query strings and moved in-anchor +0.104 while cross-anchor fell −0.083. Recent work has been trading between the two, not lifting both.

Noise floor

An operational slip launched the same condition twice; both completed all 96 episodes and gave SR 0.438 vs 0.427, with six of seven per-target SRs identical. H and I (I added only instrumentation) gave 0.448 vs 0.438. Two independent repeats agree that run-to-run noise is about one episode — so a two-or-three episode difference is not automatically noise.

Instrumentation

The measurement that ended two rounds of guessing

Twice, a conclusion was drawn about why episodes failed, acted on, and turned out to have been a guess — because the episode record could not separate “the agent never pointed a camera at the new location” from “it did, and the detection fell under the gate”. Those have entirely different fixes.

Why

Testing the centre pixel alone is far too permissive — an object nine tenths hidden behind a chair back, with only its middle showing, passes. An instrument that counts those as “the agent looked at it” understates in-situ recall by exactly the frames where the detector had no chance.

It is ground truth, and the contract is absolute: the agent is never given it, never sees these fields, and nothing in that file writes to the agent. That is why it lives on the runner’s side rather than beside the perception it measures.

Perception

The vocabulary is not a detail

An open-vocabulary head does not detect objects; it scores names, and runs class-competitive NMS over its own vocabulary. Which names are in the list changes what gets found.

The name must be the one the detector answers to. “pitcher” scores 0.00 on the YCB asset at every resolution and against eight synonyms; “blue plastic pitcher” reaches 0.71. Over 96 episodes the agent had the tomato soup can at least half visible in 431 keyframes and the detector named it twelve times.

But it must be the specific name, not the highest-scoring one. Re-probed at the dynamic poses, one candidate swapped into the vocabulary at a time:

Condition J

Took the top scorers, and they cost more than they were worth. On their own targets they were a large win — soup can recall 0.03 → 0.21, SR 0.083 → 0.500 — but the rest of the vocabulary gave back eight episodes for their seven, because “cylindrical can” describes a shape the pitcher and the bleach bottle also have. The cracker box went recall 0.32 → 0.58 and SR 0.667 → 0.333. K kept “tin can” and “red plate”, and took in-anchor to its best value of the campaign.

box and book are deliberately absent from the vocabulary. A generic class that fits a target loosely takes the detection away from the specific class that fits it exactly. Honesty

What this cannot show

The benchmark’s relocations are not semantic

Of 53 moves whose destination surface is mapped, objects land on: bed 26, desk 19, table 6, cabinet 3, nightstand 3, bench 2, stool 2 — and 37 of the 53 land on a category the affinity table does not list for that class. A tomato soup can is put on a bed seven times.

Affinity alone is no better than arbitrary order, and multiplying it in makes proximity worse. So absence from a six-entry list is not evidence (UNLISTED_AFFINITY = 0.5) and the ranking that remains is softened to a tie-breaker (AFFINITY_POWER = 0.5). This is a limitation of the benchmark, not a result about semantic priors: on a benchmark that moved objects the way people do, a stronger affinity term would be worth more.

Perception improved across the board and SR did not move

In-situ recall 0.357 → 0.471 and false-positive-only episodes 20 → 6 between I and K, for an overall SR of 0.438 → 0.448. The gains are landing where episodes were already being won.

Offline ranking metrics are scale-blind

A change that improved every ranking number switched the search line off, because the offline scorer measured order and the live system also reads magnitude. Pilot before trusting a proxy.

Testing

Behaviour locks

Nearly every constant here was chosen by an experiment. Unit tests prove the pieces still work; they cannot prove the assembled agent still does the same thing — and that is the only claim a refactor of calibrated code is allowed to make. Three locks exist for exactly that.

LockWhat it catches
test_config_snapshot 211 flattened defaults, pinned. A constant can only change when someone changes the snapshot too — which puts it in the diff as what it is, rather than as a line lost in a file move.
test_episode_record_schema The 65 episodes.jsonl keys, derived the way the runner builds them. Nine analysis scripts read this record by name and none would fail loudly on a drop — they would report zero, and the conclusion drawn from that zero would be wrong.
test_trajectory_lock A real authored episode, hashed. The stub fixture (120 steps, no GPU) covers mapping, keyframing, frontier selection and the give-up nets; the dynamic fixture (real detector + presence + search posterior, 300 steps) reaches DONE at step 236 having inspected three surfaces and made 1501 belief updates.
Detail

The dynamic lock asserts a counter fingerprint before the action hash, on purpose. presence_negative 477 → 471 names the module that moved; a bare hash mismatch says only that something did.
